## AI prompts inside the app
_The instructions the app itself gives its AI (e.g. "pull places out of this caption", "rank these places for this group"). These matter for your evals._
| Where | Prompt | Version notes |
|-------|--------|---------------|
| Ask box v1 (Stage 1, retired) | "You are Bucketful AI, a planning assistant inside a friend-group app used in Mumbai, India. Today is … Group: … People and what we know about them: (each member's likes/dislikes from the taste swipe) · Group memory: … · The group's bucket list as JSON … · Question from … Rules: prefer bucket-list places (copy the exact id); at most 2 new places, only real well-known ones, otherwise describe the kind of place; respect everyone's constraints, and only the people coming if named; prices approximate per person in ₹; never claim exact hours or bookings; category must be one of bars, cafe, food, sunset, shows, workshop; reply with JSON only {reply, suggestions[≤3]}" (full text in `bucketful.html`, function `buildPrompt`) | v1, Stage 1. Fallback when AI is off: matches bucket-list places by keywords |
| Place extraction (`supabase/functions/ai/index.ts` → `EXTRACT_SYSTEM`) | Reads what was shared (public link preview, video title, Google Maps place name, or pasted text) and returns only places actually named, with category, area, price if stated, and confidence `sure` or `partial`. If no name is given: one `partial` entry, and the app asks "Which place was it?" Ignores hashtags, handles and sponsors. Session 18: returns every place in a guide (up to 100) with its section heading · **v2 (Session 20): when a video is attached (YouTube link, or an uploaded reel recording) it must watch and listen: places that are only spoken (Hindi/English/Hinglish), shown as on-screen text, or visible on signs; each place gets an `evidence` tag (caption / heard in video / on screen / list)** | v1 (Session 16). Fallback without AI: matches known place names; the 5 eval links are built in |
| Ask box v2 (`ASK_SYSTEM`) | Answers a free question in 1–2 sentences + up to 3 places. Prefers bucket-list places (exact id), adds at most 2 new real places, respects group memory, says "about" for prices, never states opening hours | v2 (Session 16): runs on Yonder's server with the app's own key; Session 17: the model is Gemini (free tier) |
| Plan builder (`PLAN_SYSTEM`) | Gets: who's coming, when, moods, budget, areas, list/new/both, the group memory items that were ticked, free text, each person's likes / not-for-me, and the bucket list with who's interested and past ratings. Rules: hard limits first (diet, drinking, budget); respect list/new/both; prefer what people are interested in and like; use ratings; make the 3 options *different*; real places only; only people coming count. Each option's "why" names the people it suits | v1 (Session 16). Fallback without AI: scoring by mood, interest, taste, budget and distance |
